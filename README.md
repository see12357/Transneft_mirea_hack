
# Цифровой консультант ПАО «Транснефть»

Этот репозиторий содержит решение для хакатона «Цифровая весна» от ПАО «Транснефть». Проект представляет собой полноценного RAG-ассистента, способного отвечать на вопросы о компании на основе предоставленной базы знаний, а также взаимодействовать с пользователем с помощью голоса и анимированного аватара.

### Ключевые возможности
- Диалог в режиме вопрос-ответ на основе документа `.docx`.
- Голосовой ввод сообщений (Speech-to-Text).
- Голосовое воспроизведение ответов бота (Text-to-Speech) с выбором голоса.
- Анимированный аватар, реагирующий на состояние диалога (приветствие, размышление, речь, прощание).
- Защита от базовых промпт-инъекций и естественное ведение диалога.
- История диалога для каждого пользователя с использованием Redis.
- Полностью контейнеризированное решение, разворачиваемое через Docker Compose.

## 🚀 Технологический стек

- **Бэкенд:** FastAPI, Python 3.10, LangChain, PyTorch
- **Фронтенд:** React, Material-UI, Nginx
- **AI/ML:**
  - **LLM:** `gemma3:4b-it-qat` (через Ollama)
  - **Embedding:** `Qwen/Qwen3-Embedding-0.6B`
  - **Reranker:** `cross-encoder/ms-marco-MiniLM-L-6-v2`
  - **Speech-to-Text (ASR):** `nvidia/stt_kk_ru_fastconformer_hybrid_large`
  - **Text-to-Speech (TTS):** `utrobinmv/tts_ru_free_hf_vits_high_multispeaker`
  - **Векторная база:** FAISS
- **Инфраструктура:** Docker, Docker Compose, Redis

## ⚙️ Установка и запуск

Проект полностью контейнеризирован и готов к запуску. Мы предоставляем два сценария: быстрый старт с готовой базой знаний и пересборка индекса с нуля.

### Вариант 1: Быстрый старт (Рекомендуемый)

Этот вариант использует готовую векторную базу (`faiss_index_gemma`), которая уже включена в репозиторий. **Выполнять локальную индексацию не нужно.**

#### 1.1 Предварительные требования
- Установленный [Docker](https://www.docker.com/get-started/)
- Установленный [Docker Compose](https://docs.docker.com/compose/install/)

#### 1.2 Запуск
1.  **Клонируйте репозиторий:**
    ```bash
    git clone https://github.com/ВАШ_АККАУНТ/Transneft_mirea_hack.git
    cd Transneft_mirea_hack
    ```
2.  **Запустите Docker Compose:**
    Находясь в корневой папке проекта, выполните команду:
    ```bash
    docker-compose up --build -d
    ```
    - **Внимание!** Первый запуск будет долгим (20-40 минут), так как будут скачиваться все AI-модели (~25 ГБ). Последующие запуски будут быстрыми.

3.  **Проверка статуса:**
    Следите за логами бэкенда. Когда увидите сообщение `Сервер готов к работе`, система запущена.
    ```bash
    docker-compose logs -f backend
    ```

4.  **Доступ к приложению:**
    - **Фронтенд:** Откройте в браузере `http://localhost`
    - **API бэкенда (документация):** `http://localhost:8000/docs`

5.  **Остановка проекта:**
    ```bash
    docker-compose down
    ```

### Вариант 2: Пересборка векторной базы с нуля

Этот вариант нужен, только если вы хотите **изменить или обновить исходный документ** (`.docx`), на котором обучался ассистент.

1.  **Установка локальных зависимостей:**
    Создайте и активируйте виртуальное окружение, затем установите зависимости.
    ```bash
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r backend/requirements.txt
    ```

2.  **Создание FAISS-индекса:**
    - Поместите ваш новый исходный документ `.docx` в папку `backend/data/`.
    - Удалите старую векторную базу: `rm -rf backend/data/faiss_index_gemma`.
    - Запустите скрипт индексации:
      ```bash
      python backend/indexing.py
      ```
    - Процесс может занять 3-10 минут. После его завершения в `backend/data/` появится новая папка `faiss_index_gemma`.

3.  **Запуск Docker:**
    После создания нового индекса следуйте инструкциям из **Варианта 1** (начиная с пункта 1.2).

## 🔬 Оценка качества и бенчмарк (`ev.py`)

Для оценки качества RAG-системы предусмотрен скрипт `ev.py`. Он запускается локально, без Docker.

### Результаты бенчмарка

Оценка проводилась на 25 вопросах из файла `benchmark.csv`.

| Метрика                      | Значение | Описание                                                                                |
| ---------------------------- | :------: | --------------------------------------------------------------------------------------- |
| **ROUGE-L**                  |  0.5793  | Сходство сгенерированного ответа с эталонным на уровне предложений (смысловая близость).    |
| **BLEURT-20** (среднее)      |  0.7726  | Обученная метрика, оценивающая семантическую и синтаксическую корректность ответа.      |
| **Semantic Answer Similarity** |  0.8731  | Косинусное сходство эмбеддингов эталонного и сгенерированного ответов (на BGE-m3).        |
| **MRR@4** (ретривер)           |  0.5733  | Как быстро ретривер находит релевантный документ среди первых 4-х.                       |
| **NDCG@4** (ретривер)          |  0.6105  | Качество ранжирования документов (учитывает позицию релевантного документа).            |

**Вывод:** Полученные метрики демонстрируют высокое качество как системы поиска информации (ретривера), так и генерации ответов. Особенно высокий показатель `Semantic Answer Similarity` (0.87) говорит о том, что модель генерирует ответы, очень близкие по смыслу к эталонным.

### Нюансы и запуск бенчмарка

1.  **Предварительные требования:**
    - Установленный и запущенный [Ollama](https://ollama.com/) на вашем компьютере.
    - Скачанная модель для Ollama: `ollama pull gemma3:4b-it-qat`.
    - Установленные локальные зависимости (см. пункт "Пересборка", шаг 1).

2.  **Подготовка зависимостей для метрик:**
    Некоторые метрики (например, `BLEURT`) требуют скачивания дополнительных файлов. Для автоматизации этого процесса запустите специальный скрипт:
    ```bash
    python backend/download_dependencies.py
    ```
    Эта команда создаст папку `checkpoints` со всем необходимым.

3.  **Запуск оценки:**
    ```bash
    python backend/ev.py
    ```
    Скрипт выполнит все вычисления и выведет таблицу с метриками в консоль.
